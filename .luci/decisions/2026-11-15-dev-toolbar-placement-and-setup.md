# 2026-11-15: The dev toolbar sits at the bottom, describes every mode, and installs itself

## Context
The user found the dev toolbar odd: closed, Luci waits bottom-right; open, the bar appeared at the top. The mode switch sat higher than the tools, Feedback and Capture said nothing about what they are for (Layout does, through its Select hint), and adding the toolbar to an app meant pasting a script tag by hand, which is hard for designers. Agentation (the comparison the user gave) needs `npm install`, a hand edit of the React root and, for the agent, an MCP command and an endpoint prop. The user approved the plan and asked for a second, equally simple way in for people who skip it at first.

## Decisions
1. **Mode switch centred**: the segmented control's `align-self: flex-start` (right for forms) no longer applies in the bar.
2. **Bottom placement, dev toolbar only**: the dev toolbar sets `data-place="bottom"` on each mode's host; the shared styles place the cards for it with `:host([data-place="bottom"])`. Everything opens from the bar (user's correction, same day: panels at the top edge read as the extension's): hints and panels sit just above it and rise into place, a panel takes the hint's place while open, tooltips open upwards. The extension keeps the top, where its button is. No Top/Bottom setting: the bar follows its launcher.
3. **Grows from the launcher**: opening from Luci's button scales and fades the bar out of that corner (220 ms, Web Animations, opacity and transform only, none under reduced motion). The launcher and the connecting pill follow Dock left or right.
4. **Capture's column**: a bar inside it no longer applies its own offsets a second time (it sat 24 px from the window's edges instead of 12; this also moves the extension's bar to 12 px).
5. **Mode descriptions**: Feedback and Capture show a card while nothing in them is active, Luci watching (the kit's "toolbar idle" pose), one line on what the mode is for and its keys. Capture shows it after the first-run greeting. Words in `COPY.devToolbar.intro`.
6. **Setup without editing code**: `luci toolbar` finds the app's root file (Next.js app/pages, SvelteKit app.html, an Astro layout, else index.html in the root, src/ or public/) and adds a loader before `</body>` between `luci:toolbar` comments. HTML: an inline script that loads toolbar.js only on localhost, 127.0.0.1 or [::1], so a deployed site is unchanged; Next.js: a script behind `NODE_ENV === 'development'`. Nothing is installed. `luci toolbar remove` restores the file exactly; `--dry-run` and `--port` exist.
7. **Three ways in**: `luci init` asks (yes by default) in a terminal, `--toolbar` adds it without asking, and `--yes` never edits app files (it prints the command). **Second chance**: `luci serve` asks again while the toolbar is missing (with the port it serves on), and says where it is when present. **Agent path**: the agent block tells every agent to run `luci toolbar` when the user asks for the toolbar.
8. **The extension's bar moves anywhere** (user request, same day: it covered header buttons and links in the top-right corner): drag it by its own background, a separator or Luci's head (4 px before it counts, so a click on Luci still opens the menu). It is kept per site in the UI preferences as the nearest corner and the distances from its edges, clamped inside the window on resize. Cards open on the side with room (below a bar in the top half, above one in the bottom half, aligned to its side) and tooltips flip with them. Dock Right or Left puts it back in that top corner. The extension's Toolbar does this itself (`movable`).
9. **The dev toolbar moves too** (user request, same day): placed from outside its modes, through each host's `data-h`, `data-v`, `--luci-x` and `--luci-y`, which the shared styles use for the bar and its cards (so Feedback, Layout and Capture behave alike). Dragged the same way; kept as `devPlace` in the UI preferences, apart from the extension's place. Luci's button, the connecting pill and the grow animation follow the bar's corner. Dock Right or Left in any menu clears both places.
10. **One Luci version**: `LUCI_VERSION` (0.3.0, the finished v0.3) in `@luci/ui`; the root package.json, the CLI, the extension and luci-mcp say the same, and a test keeps them equal. Bump them together on the way to v1.
11. **Repository pill**: GitHub's mark (Octicons `mark-github`, MIT; added to the kit as approved file icon `github`, in THIRD_PARTY_NOTICES) and `v0.3.0` in the code font, top right of every menu. `LUCI_REPO_URL` is null until the repository is public: the pill then shows the version and says the link is coming.
12. **"Take Luci home."**: a ginger-tinted card in the extension's menu only (no pop-up: BRAND.md, not an attention seeker): "In your project, Luci also takes notes, plans layouts and remembers your rules. Free. Nothing leaves your machine." Set up Luci opens the help page's new section (the repository once it is public).
13. **Settings rows**: the words wrap beside the control, which keeps its place on the right (a longer hint had pushed Right/Left onto its own line).
14. **Luci's button moves on its own** (user request, same day): the dev toolbar's closed button drags anywhere without opening the bar; it shares the bar's place, so the bar grows from it. The dock switch reads Left | Right (screen order), Right by default.
